# .agent — 에이전트 공용 자산

이 저장소의 에이전트 스킬 **원본**은 `.agent/skills/` 에 둔다. 도구별 디렉터리(`.claude/` 등)는
원본을 복제하지 않고 심볼릭링크로 같은 실체를 가리킨다. 어떤 에이전트로 열든 같은 규칙이 로드된다.

```
.agent/skills/<스킬>/SKILL.md   # 원본 (여기만 편집한다)
.claude/skills -> ../.agent/skills
```

## 스킬 목록

- `documents-first` — 이 저장소의 결정·진행경과·설계방침은 `documents/` 가 SSOT다. 맥락에 의존하는 작업의 진입 규칙
- `test-first-implementation` — 구현은 실패하는 테스트(RED)에서 시작하고, 완료는 e2e 통과로 닫는다

## 스킬을 추가·삭제할 때

1. `.agent/skills/<이름>/SKILL.md` 를 만들거나 지운다. `.claude/skills` 는 디렉터리 전체를 가리키므로 링크 작업은 필요 없다.
2. 위 목록을 갱신한다.
3. 다른 도구를 붙일 때는 그 도구의 스킬 경로에서 `.agent/skills` 로 **상대 경로** 링크를 건다.
   절대경로 링크는 팀원 머신에서 깨진다.

## `SKILL.md` 작성 기준

- `description` 은 3인칭으로, **무엇을 하는가 + 언제 켜지는가**를 함께 적는다. 사용자가 실제로 쓸 법한 트리거 문구를 심는다.
- `description` 에 절차를 요약하지 않는다. 요약하면 에이전트가 본문을 읽지 않고 요약대로 행동한다.
- 본문은 짧게 유지한다. 모델이 이미 아는 것은 쓰지 않는다.
- 선택지를 나열하지 않는다. 기본값 하나를 정하고, 그 기본값이 깨지는 조건에서만 대안을 둔다.
- 규칙에는 검증 가능한 관문을 붙인다 — 체크리스트, 통과 전 진행 금지, 실패 시 보고 형식.
- 압박받으면 건너뛰는 규율에는 금지문과 **합리화 대응표**를 붙인다. "가급적", "고려하라" 는 무력하다.
- 경로는 항상 저장소 상대 경로로 쓴다. 개인 머신 경로·개인 작업 환경은 적지 않는다 (`documents-first` §6).
