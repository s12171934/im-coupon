# 개인화 소비 시나리오

## 결정

- 2026-09-16 — 같은 날로 압축되던 개인화 시드 120건을 날짜별 방문 시나리오 100행으로 교체했다. seed와 runtime 모두 반영한다.
- 김하람은 분식 1·3·5·7일 전, 횟집 4·6일 전 방문으로 구성한다. 유효 방문일은 분식 4일·횟집 2일이다.
- 빈도뿐 아니라 최근성·가게 영향력 상한 2·설명 벡터 유사도가 적용된다. 개인화 점수가 방문 비율과 같지는 않으며 최종 발급에는 회복 점수도 영향을 준다.

## 과거 내용·벡터의 처리

원본 공공 내용과 모델의 확인 시각·벡터 값은 변경하지 않는다. 현재 설명·벡터를 복제한 `mock-history:<기준 KST 일자>:<원본 버전>`을 추가하고, 시연에서만 120일 전부터 이용 가능했다고 가정한다. `sourceKind: mock`과 `derivedFromContentVersion`으로 원본과 구분한다. 실제 과거 영업·메뉴·모델 확인 사실이 아니며 새 임베딩을 학습한 것도 아니다.

현재 발급 후보는 더 최근의 원본 내용·벡터를 사용한다. 합성 과거 소비만 mock 버전을 참조한다. 원본 12건에 시연 버전 12건이 추가되어 내용·벡터가 각각 24건이다.

## 재생성

`node scripts/generate-personal-fit-mock.mjs [기준시각 ISO]`

기준 시각 전의 완료된 KST 날짜 정오에 방문을 배치한다. 출력은 기존 `merchant-contents`, `merchant-vectors`, `personal-fit-events`와 새 `personal-fit-scenarios` 컬렉션이다. 기본 seed와 runtime을 함께 갱신하며 `IM_COUPON_DATA_DIR`로 runtime 경로를 지정할 수 있다.

외부 거래와 그 거래가 참조하는 mock 버전은 보존한다. 나머지 이전 생성본은 교체한다. 두 목적지를 먼저 읽고 원본·참조를 확인한 뒤 내용·벡터를 이력보다 먼저 저장한다. 각 파일은 임시 파일로 교체하지만 다중 파일 트랜잭션은 아니다. 기준일이 지나 이력이 90일 창을 벗어나면 재생성한다.

상권회복용 3개월 비교 거래와 점수 정책은 변경하지 않는다. 생성 결과는 총 100행, 시민 20명이며 김하람의 분식 4일·횟집 2일을 생성 요약에서 확인했다. 이 요약은 실제 점수 계산의 실행 결과가 아니다.
