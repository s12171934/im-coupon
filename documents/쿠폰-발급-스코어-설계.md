# 쿠폰 발급 스코어 설계

> 작성·정리: 2026-09-13
> 상태: 설계 문서. 아래 변경은 애플리케이션 코드에 아직 반영하지 않았다.

## 1. 목적과 설계 범위

**시민이 실제로 방문할 수 있는 지역의 저매출 지점에 소비를 유도한다.** 이를 위해 지원이 필요한 지점과 쿠폰을 사용할 시민을 연결하고, 미사용 쿠폰 누적과 반복 발급을 조절한다.

평가 단위는 **가맹점 × 시민 조합**이다. ‘가맹점 A의 쿠폰을 시민 1에게 발급하는 경우’를 하나의 후보로 보고, 후보 중 한 쌍을 선택해 쿠폰 1장을 발급한다. 이 문서에서 ‘지점’은 평가 대상 가맹점을 뜻한다.

### 1.1. 정해진 설계와 남은 정책

| 구분           | 내용                                                                    |
| -------------- | ----------------------------------------------------------------------- |
| 필수 발급 조건 | 활동 지역 일치, 시민당 사이클별 최대 1회 발급                           |
| 평가 신호      | 소비 선호, 쿠폰 사용 가능성, 발급 균형, 보유 부담                       |
| 저매출 지원    | 매출 수준으로 지점별 목표 발급 비중을 정하고 목표 대비 실제 발급량 평가 |
| 신호 내부 계산 | 채택한 하위 기준을 0~1로 환산한 뒤 단순 평균                            |
| 신호 점수      | `0.1 + 0.9 × 평균 환산값`, 범위 0.1~1.0                                 |
| 최종 점수      | 4개 신호의 가중평균. 초기 가중치는 모두 1                               |
| 사용률 보정    | 지역·업종 등의 기준 사용률과 실제 이력을 결합                           |
| 별도 검토안    | 신규 시민·지점에 일부 발급 기회 배정                                    |
| 미정 정책      | 사이클 기간, 지역 단위, 개별 환산 기준, 신규 기회 비율 등 — 9절 참조    |

**저매출·일반 지점 3:1, 초기 사용률 50%, 보정 건수 10건, 일반·신규 발급 90:10은 설명·시뮬레이션용 예시다.** 운영값으로 확정한 수치가 아니다. 초기 신호 가중치 1은 동일 중요도로 시작하기 위한 설계값이다.

### 1.2. 현재 구현과의 차이

현재는 `CouponsService.issue()`가 후보를 적재하고, `selectCandidate()`가 `randomSignal.score()`를 호출해 가중합의 최고점 후보를 선택한다. 동점이면 목록에서 먼저 나온 후보를 선택한다. `signal.ts`는 실행 단계가 아닌 타입 계약이다.

이 설계는 랜덤 점수를 4개 평가 신호로 대체하고 지역·사이클 필터와 최종 가중평균을 도입한다. 동점 선택 방식은 미정이며, 랜덤 점수를 없애더라도 동점 후보 사이의 무작위 선택은 별도로 둘 수 있다.

기존 [쿠폰 도메인 규칙](쿠폰-도메인-규칙.md)의 5개 신호 구상과 구성에 차이가 있다. 이 문서는 발급 점수의 구체화 범위를 다루며, 가맹점 마케팅 수요는 이번 설계 범위에 포함하지 않는다. 기존 도메인 문서와의 최종 통합은 별도 결정 사항이다.

## 2. 책임과 데이터 구성

### 2.1. 역할 분리

| 구성               | 책임                                                 |
| ------------------ | ---------------------------------------------------- |
| `Candidate`        | 평가 대상 가맹점과 시민 전달                         |
| `SignalContext`    | 평가에 필요한 데이터와 공통 기준 전달                |
| 후보 필터          | 발급할 수 없는 조합 제외                             |
| `Signal`           | 적재된 데이터로 목적별 점수 계산                     |
| 엔진               | 신호 점수의 가중평균과 후보 선택                     |
| 발급 서비스·저장소 | 사이클 확인, 쿠폰 생성, 중복 발급 방지와 일관된 저장 |

통계는 후보 평가 전에 적재해 공유한다. 각 `score()`는 가맹점·시민 식별자와 업종으로 필요한 값을 찾으며, 후보마다 저장소를 조회하지 않는다. 점수 계산에 쓰는 데이터와 필터에 쓰는 데이터는 재사용할 수 있다.

### 2.2. SignalContext의 5개 데이터 묶음

| 묶음             | 주요 데이터                                                                                                  |
| ---------------- | ------------------------------------------------------------------------------------------------------------ |
| 업종 통계        | 최근 발급 수·비중, 지점 수                                                                                   |
| 지점 통계        | 매출, 발급·사용 건수, 지역·위치                                                                              |
| 시민 통계        | 전체 소비 금액, 발급·사용 건수, 미사용 유효 쿠폰 수, 마지막 발급 시각, 활동 지역, 현재 사이클 발급 완료 여부 |
| 시민 × 업종 통계 | 소비 금액·비중·횟수·마지막 소비 시각, 해당 업종 미사용 유효 쿠폰 수                                          |
| 시민 × 지점 통계 | 발급·사용 건수, 마지막 발급 시각, 유효 쿠폰 보유 여부, 결제 총액·횟수·마지막 결제 시각, 지역 일치 여부·거리  |

공통 기준에는 현재 사이클 식별자, 평가 기준 시각, 집계 기간과 정책 설정이 필요하다. 참고 집단의 기준 사용률과 그 원천 건수도 평가 전에 준비한다. 집계·공급 계약의 구체적인 형태는 구현 전에 정한다.

원천 건수와 보정 점수는 구분한다. 예를 들어 시민 전체 사용 건수는 시민 통계에 두지만, 후보의 지역·업종을 참고해 계산한 보정값은 후보별로 달라질 수 있으므로 시민 하나의 고정 점수로 취급하지 않는다.

### 2.3. 데이터 집계 원칙

- 발급 편중에 쓰는 최근 발급 수와 사용률에 쓰는 **관찰 완료 발급 수**를 구분한다. 사용률의 분자·분모는 같은 발급 집단을 대상으로 집계한다.
- 결제 총액과 횟수는 같은 기간으로 집계하고 마지막 결제 시각의 조회 범위를 명시한다. 금액 기준과 취소·환불 반영 방식은 미정이다.
- 쿠폰 사용 결제와 일반 결제를 구분한다. 공유 쿠폰의 최초 발급 시민과 실제 사용 시민도 구분한다.
- 정상 조회 결과 0건, 데이터 누락, 조회 실패를 구분한다. 매출 데이터 없음은 매출 0이 아니다.
- 동일 데이터를 여러 신호가 사용해도 원천 데이터는 재사용한다. 중복 정보를 별도 점수로 반복 반영하는 정도는 확인해야 한다.
- 프로토타입은 실제 집계와 교체 가능한 계약으로 목 데이터를 제공한다. 현재 발급 모델만으로 사용 완료 통계까지 확보된다고 가정하지 않는다.

## 4. 후보 필터와 사이클

### 4.1. 필수 조건과 추가 검토 조건

| 조건                          | 상태 | 처리                                         |
| ----------------------------- | ---- | -------------------------------------------- |
| 활동 지역 일치                | 필수 | 지역 조건에 맞지 않는 조합 제외              |
| 현재 사이클에 미발급          | 필수 | 이미 발급받은 시민을 모든 지점 조합에서 제외 |
| 시민별 최소 발급 간격         | 검토 | 도입하면 사이클 전환 직후의 연속 발급도 제한 |
| 동일 지점 유효 쿠폰 중복 보유 | 검토 | 도입하면 해당 지점 조합 제외                 |
| 시민·지점별 최소 재발급 간격  | 검토 | 도입하면 같은 조합의 반복 발급 제한          |

지역 조건은 예를 들어 대구 활동 시민에게 대구 지점 쿠폰을 연결하는 것이다. 같은 지역 안에서의 거리는 점수로 평가한다. 활동 지역의 정의·수집 방식과 지역 단위는 미정이며, 지역 정보가 없는 후보를 전국 대상으로 간주하지 않는다.

같은 **업종**의 쿠폰 보유는 보유 부담 점수로 조절한다. 같은 **지점**의 중복 보유 제한과 구분한다. 목표 발급 비중이나 신규 기회 정책은 필수 필터를 우회하지 않는다.

### 4.2. 시민당 사이클별 최대 1회

한 사이클에는 시민 한 명에게 쿠폰을 최대 1장 발급한다. 가맹점이 달라도 이미 발급받은 시민은 제외한다. 다음 발급 기회를 다른 시민에게 주는 것이며, 기존 쿠폰을 양도한다는 뜻이 아니다.

- 발급 완료는 쿠폰 저장에 성공한 시점에 기록한다.
- 쿠폰을 사용·공유하거나 쿠폰이 만료돼도 같은 사이클의 완료 기록은 유지한다.
- 사이클은 여러 발급 요청이 공유한다. 요청 한 번마다 새 사이클을 만들지 않는다.
- 한 사이클에 같은 지점 쿠폰을 여러 장 발급하려면 서로 다른 시민을 선택한다.

### 4.3. 사이클 식별과 종료

| 완료 기록      | 역할                     |
| -------------- | ------------------------ |
| 사이클 식별자  | 해당 발급 회차 식별      |
| 시민 식별자    | 사이클 내 중복 발급 방지 |
| 쿠폰 식별자    | 저장된 발급 쿠폰과 연결  |
| 발급 완료 시각 | 완료 시점 기록           |

`사이클 식별자 × 시민 식별자`는 성공한 발급 하나만 가리켜야 한다. 기록은 재시작 후에도 유지한다. 쿠폰 레코드에 포함할지 별도 저장할지는 미정이다.

종료 기준은 고정 기간(예: 하루) 또는 대상 시민에게 기회가 돌아간 시점 중에서 정해야 한다. 지역별 운영, 중간 유입 시민, 적합한 지점이 없는 시민의 처리도 함께 정한다. **사이클 기간과 최근 발급 통계의 집계 기간은 별도 개념**이다.

조건을 만족하는 후보가 없으면 해당 요청은 발급하지 않는다. 후보 소진만으로 완료 기록을 초기화하거나 새 사이클을 열지 않는다. 전원 발급 완료와 적합한 조합 없음의 구분·응답은 미정이다. 현재 엔진의 빈 후보 오류는 `NO_CANDIDATES`다.

## 5. 평가 신호

### 5.1. 4개 신호의 역할

| 신호             | 판단할 내용                              | 사용하는 데이터               |
| ---------------- | ---------------------------------------- | ----------------------------- |
| 소비 선호        | 시민의 업종 선호와 지점 이용 이력        | 시민 × 업종, 시민 × 지점      |
| 쿠폰 사용 가능성 | 쿠폰 사용 이력과 실제 방문 가능성        | 시민, 지점, 시민 × 지점       |
| 발급 균형        | 저매출 지원 목표 대비 발급량과 발급 편중 | 업종, 지점, 시민, 시민 × 지점 |
| 보유 부담        | 전체·해당 업종의 미사용 쿠폰 누적        | 시민, 시민 × 업종             |

모든 신호는 높을수록 발급에 유리한 점수를 반환한다. 후보 필터를 통과한 대상끼리 비교하며, 점수는 검증된 사용 확률을 의미하지 않는다.

### 5.2. 소비 선호

하위 기준은 **업종별 소비 비중·횟수·최근성**과 **해당 지점 결제 총액·횟수·최근성**이다. 업종 비중은 시민 전체 소비 금액을 분모로 계산한다. 일반 결제 이력도 활용하므로 해당 지점 쿠폰을 처음 받는 시민을 평가할 근거가 된다.

지점 결제액이 클수록 무조건 높은 점수를 주지는 않는다. 재방문 유도와 신규 지점 방문 유도 중 어떤 방향을 선택할지 정한 뒤 환산한다. 채택한 환산값은 단순 평균한다. 업종 소비와 지점 소비에는 같은 거래가 포함될 수 있으므로 중복 영향을 확인한다.

### 5.3. 쿠폰 사용 가능성

하위 기준 후보는 **시민·지점·시민×지점의 보정 사용률**과 **거리**다. 사용률은 7절의 공통 기준으로 각각 보정한다. 이력이 있는 한쪽의 사용률을 다른 쪽의 기준값으로 바로 대입하지 않는다.

채택한 하위 기준을 0~1로 환산해 평균한다. 세 사용률을 모두 채택할지는 중복 이력의 영향을 보고 정한다. 지역 필터와 거리 평가는 별도이며, 거리 계산에는 시민 활동 지역의 기준 위치와 지점 위치가 필요하다.

### 5.4. 발급 균형과 저매출 지원

지원 필요도는 **목표 발급 비중**으로 반영한다. 매출 수준에 따라 저매출 지점에 더 큰 비중을 부여하고, 최근 실제 발급량이 목표에 비해 얼마나 적거나 많은지 평가한다. 별도 매출 가산점까지 중복 반영하는 것은 기본안에 포함하지 않는다.

| 기준                   | 활용                              |
| ---------------------- | --------------------------------- |
| 지점 매출              | 목표 발급 비중 결정               |
| 최근 지점 발급 수      | 목표 비중 대비 발급량 계산        |
| 업종별 발급 수·지점 수 | 업종 규모를 고려한 발급 편중 평가 |
| 시민 전체 발급 수      | 최근 시민별 발급 집중도 평가      |
| 시민·지점별 발급 수    | 같은 조합의 반복 발급 평가        |

**목표 대비 발급량 = 최근 지점 발급 수 ÷ 지점별 목표 발급 비중**

목표 비중은 유한한 양수이며 같은 비교 범위에서 일관된 척도로 설정한다. 목표 대비 발급량이 낮을수록 추가 발급에 유리하게 환산한다. 그 값 자체가 0~1은 아니므로 공통 점수 공식에 바로 넣지 않는다.

다음은 저매출 A의 비중을 3, 일반 B의 비중을 1로 둔 예시다.

| 상황                    | 지점     | 목표 비중 | 최근 발급 수 | 목표 대비 발급량 |
| ----------------------- | -------- | --------- | ------------ | ---------------- |
| 목표 비율에 맞게 발급됨 | 저매출 A | 3         | 3회          | 1                |
| 목표 비율에 맞게 발급됨 | 일반 B   | 1         | 1회          | 1                |
| 각각 1회 발급됨         | 저매출 A | 3         | 1회          | 약 0.33          |
| 각각 1회 발급됨         | 일반 B   | 1         | 1회          | 1                |

A 3회·B 1회는 이 기준에서 균형이 같다. 각각 1회라면 A가 추가 발급에 유리하다. 둘 다 0회면 차이가 없으므로 다른 신호와 동점 규칙이 첫 선택을 결정한다.

**목표 비중은 지원량의 방향, 신호 가중치는 평가 중요도**다. 단순히 발급 수의 감점 가중치를 낮추는 것과 구분한다. 지점 기준을 환산한 뒤 채택한 업종·시민·조합 기준과 단순 평균한다.

- 3:1은 지점별 상대 비중의 예시이며, 저매출 지점 전체와 일반 지점 전체의 합계 비율이 아니다.
- 점수로 유도하는 정책이므로 정확한 횟수나 비율을 보장하지 않는다. 다른 신호·후보 수·지역·사이클 제한의 영향을 받는다.
- 새 발급은 후속 집계에 반영해야 한다. 매출 비교 기간·집단, 비중 재산정 주기, 변경 전 이력 처리와 환산 기준은 미정이다.

### 5.5. 보유 부담

하위 기준은 **시민 전체 미사용 유효 쿠폰 수**와 **해당 업종 미사용 유효 쿠폰 수**다. 각각 부담이 낮을수록 높은 값이 되도록 환산한 뒤 평균한다. 업종 보유 여부는 개수가 0보다 큰지로 알 수 있으므로 개수를 보관한다.

카페 A 쿠폰이 있는 시민에게 카페 B 쿠폰을 주려 할 때 같은 업종의 부담을 반영한다. 전체 보유 수에는 업종별 보유 수가 포함되므로 평균을 내더라도 중복 영향은 남는다.

만료됐거나 더 이상 보유하지 않는 쿠폰은 제외해야 한다. 공유 쿠폰의 소유·점유·사용 가능 상태 중 무엇을 ‘보유’로 셀지는 확정이 필요하다.

## 6. 점수 계산

### 6.1. 신호 내부: 환산값의 단순 평균

금액·거리·개수 등 원천 값을 **0~1, 높을수록 유리한 방향**으로 환산한다. 부담 정도처럼 높을수록 불리한 값이 이미 0~1이라면 `1 − 부담 정도`로 방향을 바꾼다.

**신호 환산값 = 채택한 하위 기준의 환산값 합 ÷ 하위 기준 수**

**신호 점수 = 0.1 + 0.9 × 신호 환산값**

| 평균 환산값 | 신호 점수 |
| ----------- | --------- |
| 0           | 0.1       |
| 0.25        | 0.325     |
| 0.5         | 0.55      |
| 0.75        | 0.775     |
| 1           | 1.0       |

예를 들어 전체 보유 부담의 환산값이 0.4, 업종별 보유 부담의 환산값이 0.8이면 평균은 0.6, 신호 점수는 **0.64**다.

원천 값을 환산하는 기준은 별도로 필요하다. 설명용으로 10개를 최대 부담으로 잡으면 미사용 쿠폰 0개·5개·10개 이상에 대한 유리한 방향의 환산값은 각각 1·0.5·0이다. 최대 부담 10개는 확정값이 아니다.

### 6.2. 최종 결합: 신호 점수의 가중평균

**최종 점수 = Σ(신호 점수 × 신호 가중치) ÷ Σ신호 가중치**

| 신호             | 점수 예시 | 초기 가중치 |
| ---------------- | --------- | ----------- |
| 소비 선호        | 0.8       | 1           |
| 쿠폰 사용 가능성 | 0.7       | 1           |
| 발급 균형        | 0.9       | 1           |
| 보유 부담        | 0.64      | 1           |

위 예시의 최종 점수는 `(0.8 + 0.7 + 0.9 + 0.64) ÷ 4 = 0.76`이다. 가중치를 모두 1로 시작하고 필요하면 신호별 중요도를 조정한다. 동일 후보 집합에 같은 가중치를 쓰면 가중합과 가중평균의 순위는 같고 표시 범위만 달라진다.

### 6.3. 계산 시 지킬 조건

- 각 신호 점수와 최종 점수는 모두 0.1~1.0이다.
- 하위 기준 수는 1 이상이다. 신호 가중치는 유한한 음수 아닌 값이며 합은 유한한 양수다.
- 원천 금액·거리·개수를 직접 평균 내지 않는다. 모든 신호의 하위 항목을 한꺼번에 평균 내지도 않는다. 신호별 평균을 먼저 계산해야 항목이 많은 신호가 자동으로 더 큰 비중을 갖지 않는다.
- 평균에 넣을 기준 목록을 신호별로 고정해 모든 후보에게 동일하게 적용한다. 분모용 데이터·보류 항목은 독립 평가 항목으로 세지 않는다.
- 이력 부족에는 보정·기본값을 적용한다. 후보별로 없는 항목을 임의로 빼서 분모를 바꾸지 않는다. 조회 실패나 계산 불가를 0으로 숨기지 않는다.
- 평균은 중복 정보를 제거하지 않는다. 지표 구성과 상관된 이력의 영향을 별도로 확인한다.
- 참고 집단의 사용률은 원천 건수 합으로 집계한다. 평가용 환산값의 평균과 구분한다.

## 7. 신규 후보와 이력 부족

### 7.1. 두 가지 문제의 구분

**점수 보정**은 정보 부족으로 인한 극단적인 평가를 완화한다. **기회 배정**은 점수가 낮아 계속 선택되지 않는 문제를 다룬다. 기본값이나 동점 무작위 선택만으로 신규 후보의 선택 기회 전체가 보장되지는 않는다.

| 상황                         | 처리                                  |
| ---------------------------- | ------------------------------------- |
| 소비 선호·사용률의 이력 없음 | 참고 통계나 기본값 적용               |
| 정상 조회 결과 발급·보유 0건 | 실제 값 0 사용                        |
| 평가 가능한 이력이 적음      | 실제 이력과 기준값을 보정해 결합      |
| 조회 실패                    | 이력 없음으로 바꾸지 않고 오류로 처리 |

신규 등록, 발급 기회 미수령, 관찰 가능한 사용 이력 부족은 다르다. 등록이 오래됐어도 처음 쿠폰을 받을 수 있고, 이미 발급됐어도 사용 관찰 기간이 끝나지 않았을 수 있다. 보정은 관찰 이력 수를 보고, 기회 배정은 별도의 대상·종료 정책을 따른다. 논의 중 표현한 `vi`는 기본값의 임시 표현이며 확정 필드명이나 수식이 아니다.

### 7.2. 시민·지점 조합별 처리

| 조합                  | 활용할 근거                                           | 보완할 부분                           |
| --------------------- | ----------------------------------------------------- | ------------------------------------- |
| 신규 시민 × 기존 지점 | 지점 사용 이력·매출·발급량, 지역·거리                 | 시민 이력이 부족한 기준               |
| 기존 시민 × 신규 지점 | 시민 업종 선호·사용 이력, 지역·거리, 확보된 지점 매출 | 지점 이력이 부족한 기준               |
| 신규 시민 × 신규 지점 | 지역·거리, 확보된 매출                                | 시민·지점의 이력 기반 기준 각각       |
| 기존 시민 × 기존 지점 | 각자의 이력과 조합 이력                               | 해당 조합만 처음이면 조합 사용률 보정 |

신규라고 모든 신호에 같은 기본 점수를 주지 않는다. 알고 있는 데이터는 그대로 사용한다. 기존 시민·기존 지점 사이의 조합만 처음인 경우는 그 이유만으로 신규 우선 배정 대상에 넣지 않는다.

### 7.3. 기준 사용률의 우선순위

평가 대상 지점의 지역·업종을 기준으로 다음 순서를 적용한다.

| 우선순위 | 참고 집단             | 적용 조건                     |
| -------- | --------------------- | ----------------------------- |
| 1        | 같은 지역 × 같은 업종 | 평가 가능한 이력이 충분함     |
| 2        | 같은 업종 전체        | 지역·업종 이력이 부족함       |
| 3        | 서비스 전체           | 업종 전체 이력도 부족함       |
| 4        | 초기 설정값           | 상위 집단 모두 기준에 못 미침 |

대구 카페 후보라면 **대구 카페 → 전체 카페 → 서비스 전체 → 초기 설정값** 순서다. 다른 지역 통계의 참고는 발급 지역 필터를 완화하지 않는다.

**기준 사용률 = 참고 집단의 사용 건수 합 ÷ 같은 평가 대상 발급 건수 합**

지점별 사용률의 단순 평균이 아니다. 최소 관찰 건수·기간은 미정이며, 분모가 0이거나 충분성 기준에 못 미치면 다음 집단을 본다. 조회 실패를 이력 부족으로 간주하지 않는다.

동일 후보의 시민·지점·조합별 사용률은 공통 기준에서 각각 보정한다. 시민 전체 이력에 후보의 지역·업종 기준을 적용하므로 같은 시민의 보정값도 후보에 따라 달라질 수 있다.

### 7.4. 보정 공식과 출처

**보정 사용률 = (사용 건수 + 기준 사용률 × 보정 건수) ÷ (평가 대상 발급 건수 + 보정 건수)**

| 값                  | 출처                          | 의미                                            |
| ------------------- | ----------------------------- | ----------------------------------------------- |
| 사용 건수           | 쿠폰 사용 이력                | 관찰 대상 쿠폰 중 사용된 수                     |
| 평가 대상 발급 건수 | 발급 이력·기한                | 사용 여부를 충분히 관찰한 쿠폰 수               |
| 기준 사용률         | 참고 집단 집계 또는 초기 설정 | 이력 부족 시 참고할 사용률                      |
| 보정 건수           | 정책 설정                     | 기준 사용률을 실제 이력 몇 건만큼 반영할지 결정 |

보정 건수는 실제 발급 실적이 아닌 유한한 양수 설정값이다. 기준 사용률은 0~1이며 사용 건수는 평가 대상 발급 건수 이하이다.

| 평가 대상 발급 수 | 사용 수 | 기준 사용률 예시 | 보정 건수 예시 | 보정 사용률 |
| ----------------- | ------- | ---------------- | -------------- | ----------- |
| 0                 | 0       | 50%              | 10             | 50%         |
| 1                 | 1       | 50%              | 10             | 약 54.5%    |
| 10                | 8       | 50%              | 10             | 65%         |
| 100               | 80      | 50%              | 10             | 약 77.3%    |

이력이 없으면 기준 사용률을 따르고, 이력이 쌓일수록 실제 사용률에 가까워진다. 보정 건수가 클수록 기준값의 영향이 오래 남는다. 50%·10건은 검증 전 예시값이다.

보정 사용률은 0~1의 하위 지표다. 다른 채택 기준과 평균을 낸 뒤 공통 점수 공식을 적용한다. 사용률 50%를 단독 환산값으로 쓰면 점수는 0.55다. 이 보정 공식을 금액·거리·매출에 그대로 적용하지 않는다.

사용률 집계는 다음을 지킨다.

- 충분히 관찰한 발급만 분모로 삼고, 분자도 그 쿠폰 중 사용된 수로 제한한다.
- 직접 사용인지 타인에 의한 최종 사용까지 포함하는지 정의를 통일한다. 참고 집단과 평가 대상에 같은 정의를 적용한다. 최종 정의는 미정이다.
- 참고 집단, 집계 기간, 원천 건수, 설정값을 확인할 수 있게 한다. 목 통계와 실제 통계는 같은 공급 계약을 따른다.

### 7.5. 신규 기회 배정안 — 적용 여부 미정

4개 신호는 유지하고, 별도 발급 기회에서는 선택할 후보 범위를 제한한다.

| 발급 구분 | 비중 예시 | 선택 방식                                                  |
| --------- | --------- | ---------------------------------------------------------- |
| 일반      | 90%       | 필터를 통과한 전체 후보 중 점수로 선택                     |
| 신규 기회 | 10%       | 신규 시민 또는 신규 지점을 먼저 고려한 뒤 적합한 상대 선택 |

90:10은 시뮬레이션 비교안이다. 일반 발급에도 신규 후보가 포함되므로 10%는 신규 발급 총량의 상한이 아니다. 신규 대상이 없으면 일반 발급으로 전환한다.

- **신규 시민 기회:** 적합한 지점이 있고 아직 기회를 받지 못한 시민 중 대기 시간을 고려해 정한 뒤 지점을 점수로 선택한다.
- **신규 지점 기회:** 적합한 시민이 있고 아직 기회를 받지 못한 지점 중 대기 시간을 고려해 정한 뒤 이번 사이클 미발급 시민을 점수로 선택한다.
- 둘 다 신규인 조합이면 시민·지점의 기회 이력에는 모두 기록하되, 실제 발급과 신규 기회 발급 건수는 각각 1건으로 센다.
- 필수 지역·사이클 조건은 유지한다. 저매출 목표 비중은 적합한 상대의 점수 계산에 반영하고 최종 지점별 분포도 확인한다.
- 기회를 이미 줬지만 관찰 기간이 끝나지 않은 대상을 미지원 신규로 취급해 반복 우대하지 않는다.

신규 정의·우대 종료 조건, 시민과 지점 사이의 배정 비중, 대기 시작 시각, 작은 발급량의 배정 방식은 미정이다. 비중은 성공 발급 기준으로 집계하며 신규 기회 이력은 사이클이 바뀌어도 초기화하지 않는다. 기존 발급 이력에서 알 수 있는 정보는 재사용한다.

사이클을 적합한 시민 모두에게 발급한 뒤 종료한다면 신규 시민의 별도 기회 필요성은 작아진다. 고정 기간에 종료하고 발급량이 부족하면 일부 시민이 계속 밀릴 수 있다. 어느 방식이든 신규 지점의 기회는 따로 확인해야 한다.

## 8. 발급 실행과 저장

### 8.1. 처리 순서

1. 현재 사이클, 후보 데이터, 통계와 발급 완료 기록을 적재한다.
2. 현재 사이클 미발급 시민과 지역 조건을 만족하는 지점으로 조합을 구성한다. 제한 없이 조합하면 M×N개이므로 불필요한 조합을 먼저 제외할 수 있다.
3. 도입이 확정된 추가 필터를 적용한다. 후보가 없으면 발급하지 않는다.
4. 신규 기회 배정안을 도입했다면 일반·신규 구분에 따라 선택 범위를 정한다.
5. 후보마다 4개 신호를 계산하고 가중평균으로 최고점 조합을 선택한다. 동점 규칙은 미정이다.
6. 사이클·필수 조건을 최신 상태로 확인하고 쿠폰과 완료 기록을 일관되게 저장한다. 동시 요청이 같은 시민에게 중복 발급하지 못하게 보호한다.
7. 저장 후 응답하고 후속 평가에 발급 결과를 반영한다. 다음 요청은 완료 시민을 제외한다.

### 8.2. 동시 요청과 중간 실패

**최신 발급 여부 확인부터 쿠폰·완료 기록 저장까지** 하나의 일관된 처리로 보호한다. 완료 기록만 남거나 쿠폰만 저장돼 재발급되는 상태를 만들지 않는다.

단일 프로세스에서는 발급 처리 전체를 순서대로 실행하는 방식을 우선 검토한다. 저장 작업만 직렬화하면 두 요청이 같은 시민을 미리 선택할 수 있다. 서로 다른 파일에 저장한다면 직렬화만으로 중간 실패를 해결할 수 없으므로 원자적 저장 단위 또는 복구 절차가 필요하다.

저장 성공 후 응답 전송이 실패해도 완료 기록은 유지한다. 다만 일반 발급 요청 자체는 시민을 지정하지 않으므로 시민·사이클 유일성만으로 동일 요청의 재시도를 식별할 수는 없다. 재시도 시 기존 결과 반환 등 요청 중복 처리 방식은 별도로 정해야 한다.

## 9. 미정 정책과 확인할 성과

### 9.1. 구현 전에 정할 사항

| 영역        | 남은 결정                                                                                    |
| ----------- | -------------------------------------------------------------------------------------------- |
| 지역        | 활동 지역 정의·수집 방식, 허용 지역 단위, 위치 기준, 정보 누락 처리                          |
| 사이클      | 시작·종료 조건, 지역별 운영, 대상 범위·중간 유입, 후보 소진 응답                             |
| 추가 필터   | 중복 보유 제한 도입 여부, 시민·조합별 최소 발급 간격                                         |
| 소비 선호   | 재방문·신규 방문 중 유도 방향, 하위 기준별 환산식                                            |
| 사용 가능성 | 직접 사용·최종 사용 정의, 관찰 기간, 참고 집단 최소 건수, 보정 건수, 채택할 사용률·거리 기준 |
| 저매출 지원 | 매출 비교 집단·기간, 목표 비중·갱신 주기, 목표 대비 발급량 환산식, 업종 규모 보정            |
| 보유 부담   | 공유·점유 쿠폰 집계 범위, 전체·업종별 부담 환산 기준                                         |
| 점수        | 신호별 채택 기준 목록·기본값, 중복 정보 영향, 향후 신호 가중치 조정 기준                     |
| 신규 기회   | 적용 여부·비율, 신규 정의·종료 조건, 시민·지점 배분, 대기·배정 단위                          |
| 공통 데이터 | 공급 계약, 집계 시각·기간, 결제 금액·취소·환불 기준, 매출 누락 처리                          |
| 선택·저장   | 동점 규칙, 통계 갱신, 동시성·원자적 저장·복구, 요청 재시도 처리                              |
| 기존 설계   | 도메인 규칙의 5개 신호 구상과 최종 통합                                                      |

### 9.2. 성과와 균형 확인

| 관점        | 확인할 지표                                                            |
| ----------- | ---------------------------------------------------------------------- |
| 저매출 지원 | 대상 지점 매출 변화, 목표 비중 대비 실제 발급량                        |
| 사용 성과   | 관찰 완료 쿠폰 사용률, 쿠폰으로 소비한 금액                            |
| 혜택 편중   | 시민별 발급량·페이백 수령량, 전체·업종별 미사용 보유량                 |
| 신규 기회   | 적합한 후보가 있는 신규 시민·지점의 첫 발급 대기 시간과 기회 수령 비율 |
| 배정 운영   | 일반·신규 성공 발급 수, 시민·지점 기회 건수, 필터별 제외 수            |

쿠폰 사용액만으로 매출 증가 효과를 단정하지 않는다. 비교 기간·비교군 등 효과 확인 방법은 별도로 정한다. 신규·기존 비교에서는 지역·업종과 관찰 기간도 맞춰야 한다.

먼저 목 데이터로 기본 보정만 적용한 경우와 신규 기회를 배정한 경우를 비교한다. 신규 비중, 발급량, 적합한 상대 수, 전체 이력이 없는 초기 상태를 바꿔 보되 시뮬레이션 결과를 실제 매출 효과로 취급하지 않는다. 이 문서 정리는 시뮬레이션이나 테스트를 실행했다는 의미가 아니다.
