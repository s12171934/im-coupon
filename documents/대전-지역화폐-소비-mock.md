# 대전 지역화폐 소비 mock — 폐기한 방식의 기록

## 현재 상태

2026-09-16 — 사용자 요청으로 상품 기반 소비 mock 방식을 폐기하고, 미사용 산출물과 생성기를 삭제했다. 아래 파일 목록·명령·수치는 당시 작업 기록이며 현재 실행 안내가 아니다. 앞으로 소비 데이터는 D1 업종 기준으로 seed에 반영한다.

## 결정

- 2026-09-16 — 사용자가 지정한 상품 SET2100020의 공개 컬럼 구조에 맞춰 대전 소비 mock을 생성했다. 실제 소비 데이터 구매·다운로드나 실측 통계 확보를 의미하지 않는다.
- 비교 기준은 대구가 아닌 대전 전체다. 기준월 202606과 직전 두 달 202604·202605를 고정한다. 현재 날짜의 최신 통계라는 의미는 아니다.
- 기존 D0 11개 업종은 시연용 선택 집합으로 유지한다. 이 상품의 전체 업종 목록이 11개라는 뜻은 아니며, 실제 지역화폐 사용 가능 업종이나 두 자료의 카드 업종 코드 동등성을 확인한 것도 아니다.

## 공개 상품에서 확인한 사실

상품명은 ‘농협은행X비씨카드 지역화폐 소비 데이터 이용 현황’이다. 지역화폐 이용을 월별로 집계하며 가맹점 소재지와 고객 거주지를 함께 제공한다. 대전은 농협 제공 범위에 안내되어 있다. 지역·기간은 담당자와 협의하는 공급 방식이며, 공개 페이지의 미리보기는 부산의 202606 일부 행이다. 대전 실제 금액과 3개월 제공 여부는 확인하지 못했다.

기존 공모전 CSV와 **다른 모집단·스키마**다. 일반 카드 소비 전체, 가게별 매출, 지역화폐 전체 시장 점유율로 해석할 수 없다. 이번 mock 수치는 공개 샘플 금액을 복사하거나 대전에 환산한 것이 아니다.

## 컬럼 대응

| 상품 미리보기 컬럼 | 의미 | 월별 집계 사용 |
| --- | --- | --- |
| STRD_YYMM | 기준년월 | month |
| MEGA_CTY_NM | 가맹점 시도 | 대전광역시 필터 |
| CTY_RGN_NM | 가맹점 시군구 | districtName 및 공식 코드 연결 |
| ADMI_CTY_NM | 가맹점 행정동 | 구 단위로 합산 |
| TP_BUZ_CD | 업종 코드 | categoryCode |
| SIDO_NM / CCG_NM / ADNG_NM | 고객 거주 시도·시군구·행정동 | 거주지로 상권 필터링하지 않고 합산 |
| SEX_CD / AGE_VAL | 성별·연령 | 고객 집계 차원 합산 |
| SALE_CNT / SALE_AMT | 이용 건수·금액 | count / amount, 금액 단위 원 |

상품 설명표는 성별·연령 컬럼을 SEX·AGE로 적고 미리보기는 SEX_CD·AGE_VAL로 적는다. 생성 파일은 미리보기 이름을 사용했다. 실 파일 도입 시 헤더를 확인하고 별칭을 정규화해야 한다. 기존 D0의 GENDER_CD·AGE_CD·TP_BUZ_NO·amt를 그대로 읽으면 안 된다.

`node scripts/generate-daejeon-consumption.mjs`

출력 폴더: `data/mock/daejeon-consumption/`

| 파일 | 내용 |

기존 `data/seed`나 `data/runtime`의 쿠폰 소비·개인화 이력과는 다른 집계 자료다. 이번 파일은 발급 알고리즘이나 DB 컬렉션에 자동 연결되지 않는다. 생성 스크립트는 이 폴더의 산출물만 갱신한다.

### 생성 가정

- D1 지역 코드 목록에서 대전의 5개 구를 가져온다. 구별로 첫 번째 행정동 하나와 성별·연령 조합 두 개만 사용한 작은 합성 예시다. 전체 행정동·인구 구성비를 재현하지 않는다.
- 고객 거주 구를 가맹점 구와 다르게 구성했다. 따라서 고객 주소를 기준으로 잘못 집계하는 구현을 구별할 수 있다.
- 일별 기본 건수는 구·업종 순서에 따라 70부터 증가시킨다. 5월 계수는 1.04, 6월 계수는 0.72·0.90·1.08·0.82·1.16 중 하나다. 건당 금액은 업종 순서에 따라 8,000원부터 1,500원씩 증가한다. 모두 산술 확인용 임의 값이다.
- 코드 목록 기준일과 관측월이 다르다. 2026년 4~6월의 실제 행정구역·업종 경계 일치까지 입증하지 않는다.
- 이 자료는 공개 분포에 보정된 시뮬레이션이 아니다. 저장소의 ‘공개 분포에 맞춘 mock’ 요건을 충족하려면 실제 분포 확보가 추가로 필요하다.

## 계산 정의

4월은 30일, 5월은 31일, 6월은 30일이다. 이번 데이터의 비교값은 다음과 같이 생성한다.

```text
직전 두 달 일평균 = (4월 금액 + 5월 금액) / 61
기준월 일평균 = 6월 금액 / 30
감소율 = 1 - 기준월 일평균 / 직전 두 달 일평균
대전 감소율 = 각 월에 대전 5개 구 금액을 합산한 뒤 동일 공식 적용
상대 감소율 = 해당 구 감소율 - 대전 감소율
```

이는 두 달의 모든 일자를 동일하게 취급하는 생성기 정의다. 월별 일평균을 다시 단순 평균하는 방식과 다르다. 회복 신호의 최종 정규화·가중치 공식은 이번 작업에서 확정하거나 적용하지 않았다.

감소율은 비율 값이다. `0.1`은 10% 감소, `-0.1`은 10% 증가다. 구별 감소율의 단순 평균으로 대전 감소율을 만들지 않는다. 상대 감소율은 %p 차이이며 점수로 쓰려면 별도의 변환 정책이 필요하다.

## 결측·0분모 및 품질 결과

- 기본 자료: 원시 셀 330건, 월별 165건, 도시별 33건, 비교 55건. 원시 키 중복 0건, 기대 월별 키 누락 0건, 과거 0분모 0건.
- 원시→구별→도시별 총금액은 모두 11,532,485,500원으로 일치한다. **합성 데이터의 합계**이며 실제 대전 소비액이 아니다.
- 어느 구의 해당 업종·월이 없으면 대전 합계를 부분 합산하지 않는다. `missing_region_month`와 `null`을 반환한다.
- 같은 구·업종·월이 중복되면 `duplicate_key`, 유효하지 않은 금액이면 `invalid_amount`다.
- 직전 두 달 합계가 실제 관측 0이면 `zero_denominator`이며 감소율은 `null`이다. 현재 금액만 0이고 과거가 양수이면 감소율 1을 계산할 수 있다.
- 구의 0분모와 대전의 0분모는 별도 판정한다. 구 비교가 불가능하면 상대 감소율도 `null`이다.
- 결측은 0으로 채우지 않는다. 실제 자료의 부분 성별·연령 셀 누락은 공개 스키마만으로 검출하기 어려우므로 공급자의 완결성·비공개 처리 규칙을 추가 확인해야 한다.

생성기를 실행해 산출물과 예외 데이터의 계산 결과를 확인했다. 앱 테스트·빌드·타입 검사는 실행하지 않았다.
