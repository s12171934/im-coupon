# KAN-27 발급 연결

## 결정

- 2026-09-16 — 시민을 먼저 선택한 뒤 기존 발급 가게만 비교한다. 가상 비교 가게는 발급 대상에 넣지 않는다.
- 회복 공식은 KAN-27 송준형 댓글에서 확인한 식을 사용한다. 지역 비교 기준을 대전으로 바꾼다.
- r = max(0, 1 - 현재 일평균 / 직전 두 달 일평균)
- 회복 점수 = 0.6 × clip(r / 0.25, 0, 1) + 0.4 × clip((r - max(0, 대전 감소율)) / 0.15, 0, 1).
- 월별 금액은 현재 기준월과 직전 2개월을 같은 업종으로 조회한다. 두 달의 일평균은 금액 합계 / 일수 합계다.
- 개인화 0.7·회복 0.3을 기본값으로 하고 요청에서 조절한다. 최종 점수는 가중합 / 가중치 합이다. 랜덤 신호는 제거한다.
- 현재 후보 하나라도 회복 입력이 없거나 잘못되면 요청 전체 회복 가중치를 0으로 한다. 개인화 가중치가 0으로 요청된 경우에도 결측 fallback에서는 개인화 1로 전환한다.
- 동점은 최종 점수 → 개인화 점수 → 가게 ID 오름차순이다. 모든 개인화 점수가 비활성이면 0점으로 동일 규칙을 적용하고 그 사유를 표시한다. 반복 발급 제한은 별도이며 이번 변경에는 포함하지 않는다.

## 입력과 응답

`POST /api/coupons/issue`에는 `citizenId`가 필수다. `weights`는 `personalFit`, `salesRecovery` 두 키만 받는다. 랜덤 키는 거부한다. 발급 서비스는 시민이 존재하는지 확인하고 해당 시민의 가게 후보만 준비한다.

통계 원본은 `district-consumption-monthly`, 범위·기준월은 `sales-recovery-dataset`, 지역 목록은 공공 코드 기준표를 사용한다. 저장된 비교 점수나 과거 `eligible` 판정만 신뢰하지 않고 요청마다 관측·중복·결측·분모를 다시 확인한다. 공공 가게의 지역·업종이 바뀌면 새 연결로 조회한다.

응답에는 요청 가중치, 실제 적용 가중치, 동점 규칙, 회복 활성 여부와 한국어 사유, 문제 가게 목록, 선택 가게의 감소율·점수·기준월·mock 출처를 표시한다. 결측 회복 점수는 `null`이며 실제 0점과 구분한다. 저장소 읽기 자체가 실패하면 기존 STORAGE_FAILURE로 거부한다.

## 미결·검증

- [ ] 자동 테스트·타입 검사·빌드는 사용자 요청 시 실행한다. 이번 구현에서는 테스트를 작성·갱신하되 실행하지 않는다.
- [ ] 실제 소비 통계 연결, 반복 발급 제한은 후속 범위다.

## 구현 및 남은 검증

시민 필수 요청 계약, 서버 회복 계산·전체 fallback·가중평균·결정적 동점 처리, UI 시민 선택·사유 표시를 구현했다. 랜덤 신호 파일과 주입을 제거했다. 쿠폰 식별자의 UUID 생성은 점수와 별개로 유지한다.

공식·결측·중복·0분모의 단위 테스트, 시민 고정·저장·개인화 fallback·입력 거부의 HTTP 테스트, 시민 선택·결측 결과 표시의 화면 테스트를 작성하거나 갱신했다. 기존 E2E에도 시민 선택 단계를 추가했다. 자동 테스트·타입 검사·빌드·브라우저 실행 결과는 아직 확인하지 않았다.

기존 클라이언트가 시민 없이 발급하거나 `random` 가중치를 보내면 이제 400으로 거부된다. 웹과 API 변경을 함께 적용해야 한다. 반복 발급은 허용되므로 같은 입력으로 같은 가게가 다시 선택될 수 있다.

## 소비 시연 발급 400 수정

- 2026-09-16 — 소비 시연 화면의 별도 발급 버튼이 빈 객체를 보내는 누락을 수정했다. 화면에서 선택한 쿠폰 소유자의 ID를 `citizenId`로 전달하며, 목록에 없는 소유자는 발급하지 않는다. 발급 전용 화면과 소비 시연 화면 모두 같은 시민 필수 계약을 사용한다. 선택 변경·빈 시민 목록 회귀 테스트를 추가했으며 실행하지 않았다.
