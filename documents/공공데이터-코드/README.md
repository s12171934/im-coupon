# 공공 상가정보 코드 안내

상가 API의 지역·업종 코드를 이름으로 찾아 사용하는 기준표다. 기존 목 가게에 등장한 업종만 모으지 않고 **코드 조회 API 전체 응답**을 저장한다.

- [지역 전체표](지역-전체표.md): 지역 구분, 전국 시도·시군구·행정동의 명칭 → 코드, 상위 지역, 자료 기준일.
- [업종 전체표](업종-전체표.md): 전체 대·중·소분류의 명칭 → 코드, 상위 분류, 자료 기준일.
- 원천 스냅숏: `data/reference/store-codes.json`.
- 앱 공통 타입: `packages/contracts/src/store-codes.ts`.
- 앱이 읽는 생성 데이터: `packages/contracts/src/store-code-data.ts`. 직접 편집하지 않는다.

정상 코드 목록 응답 276건(업종 3회 + 시도 1회 + 시군구 16회 + 행정동 256회)을 기록했다. 모든 시도·시군구의 하위 목록 요청이 있고, 저장된 코드의 중복·부모 누락은 없다. 현재 상가 시드 12곳의 소분류 코드도 모두 전체 목록에 존재한다. 이 확인은 코드 데이터 수집·연결 확인이며 앱 테스트 실행 결과는 아니다.

## 지역 선택과 요청 값

| 화면에서 선택하는 값 | 요청 파라미터 | 전송 코드 | 의미 |
| --- | --- | --- | --- |
| 시도 | `divId` | `ctprvnCd` | 시도 단위로 상가 조회 |
| 시군구 | `divId` | `signguCd` | 시군구 단위로 상가 조회 |
| 행정동 | `divId` | `adongCd` | 행정동 단위로 상가 조회 |
| 대전광역시 | `key` | `30` | `divId=ctprvnCd`와 함께 사용 |
| 대전광역시 동구 | `key` | `30110` | `divId=signguCd`와 함께 사용 |
| 대전광역시 중구 | `key` | `30140` | 동일 |
| 대전광역시 서구 | `key` | `30170` | 동일 |
| 대전광역시 유성구 | `key` | `30200` | 동일 |
| 대전광역시 대덕구 | `key` | `30230` | 동일 |
| 대전광역시 유성구 신성동 | `key` | `30200550` | `divId=adongCd`와 함께 사용 |

지역 코드의 자리수는 시도 2자리, 시군구 5자리, 행정동 8자리다. 선행 0·식별자 의미를 보존하기 위해 숫자가 아닌 문자열로 저장한다. 동명이 있는 지역은 부모 지역까지 함께 확인한다.

법정동은 행정동과 다른 구분이다. `baroApi`에는 법정동 목록(`catId=zone`)도 있으나, 이번 상가조회 `storeListInDong`의 `divId`에는 법정동을 받지 않는다. 법정동 코드를 행정동 입력에 대신 넣지 않는다. 이 문서의 전체 지역 범위는 상가조회에 사용하는 시도·시군구·행정동이다.

## 업종 선택과 요청 값

| 명칭 → 코드 예시 | 파라미터 | 값 |
| --- | --- | --- |
| 음식 → I2 | `indsLclsCd` | `I2` |
| 한식 → I201 | `indsMclsCd` | `I201` |
| 횟집 → I20111 | `indsSclsCd` | `I20111` |

정확한 명칭은 전체표와 공공 API 응답을 기준으로 한다. 대·중·소분류는 계층이며 자유롭게 섞는 세 가지 태그가 아니다. 소분류를 고르면 그 소분류에 속하는 중분류·대분류를 함께 선택한다. 상위 분류를 변경하면 기존 하위 분류를 비운다.

예를 들어 **대전 유성구 신성동의 횟집** 조회는 다음 요청으로 연결된다. 인증키는 서버가 추가한다.

```text
/api/store-api/stores?divId=adongCd&key=30200550&indsLclsCd=I2&indsMclsCd=I201&indsSclsCd=I20111&pageNo=1&numOfRows=20
```

빈 업종 값은 해당 분류로 제한하지 않는다는 뜻이다. 전체 업종 조회는 세 파라미터를 모두 생략한다. 공모전 D0 CSV의 업종 코드와 D1 상가정보 코드는 서로 다른 체계이며, 이번 목록 수집이 D0↔D1 대응표를 확정한 것은 아니다.

## 코드 목록을 가져오는 API

공통 기준 주소: `https://apis.data.go.kr/B553077/api/open/sdsc2`.

| 필요한 목록 | 오퍼레이션 | 인증키 외 요청 파라미터 |
| --- | --- | --- |
| 업종 대분류 전체 | `largeUpjongList` | `type=json` |
| 업종 중분류 전체 | `middleUpjongList` | `type=json`, 상위 필터 생략 |
| 업종 소분류 전체 | `smallUpjongList` | `type=json`, 상위 필터 생략 |
| 전국 시도 | `baroApi` | `resId=dong&catId=mega&type=json` |
| 시도 아래 시군구 | `baroApi` | `resId=dong&catId=cty&ctprvnCd={시도코드}&type=json` |
| 시군구 아래 행정동 | `baroApi` | `resId=dong&catId=admi&signguCd={시군구코드}&type=json` |

`baroApi`의 `catId`는 **코드 목록 조회용**이다. 실제 상가조회에서 사용하는 `divId`와 서로 바꾸어 넣으면 안 된다. 전체 시도마다 시군구를 가져오고, 반환된 모든 시군구마다 행정동을 가져온다. 지역·업종을 임의로 제외하지 않는다.

## 갱신과 누락 확인

```sh
# apps/api/.env의 DATA_GO_KR_SERVICE_KEY 사용
pnpm data:sync-store-codes

# 외부 호출 없이 저장된 스냅숏으로 타입 데이터·문서만 재생성
node scripts/sync-store-code-catalog.mjs --from-snapshot
```

- 수집은 읽기 전용이다. 코드 변경 요청 API를 호출하지 않는다.
- 호출 제한을 고려해 순차 요청과 재시도를 사용한다. 최근 1시간 내 성공 응답은 `.tmp/store-code-responses`에 저장해 재개 시 재사용한다.
- 어떤 목록이든 최종 조회에 실패하면 부분 결과를 적용하지 않는다. 인증키·인증키가 포함된 요청 URL은 산출물과 로그에 저장하지 않는다.
- 코드 중복, 필수 값 누락, 중분류·소분류의 부모 누락, 행정동·시군구의 부모 불일치를 수집 과정에서 차단한다.
- 스냅숏의 `requests`는 각 코드 목록 요청 조건과 반환 건수를 보존한다. 따라서 모든 시도·시군구를 방문했는지 확인할 수 있다.
- API 목록 기준일과 개별 상가 응답의 기준월은 다를 수 있다. 이번에 확인한 지역 목록은 `2026-07-01`, 상가 시험 응답은 `202606`이었다. 과거·현재 코드의 병합이나 이름 변경을 임의로 추정하지 않는다.
- 첨부 가이드 2026-08-05판의 2026년 7월 시도 표와 API는 모두 16개 시도를 제공한다. 예전 코드 개수나 명칭으로 덮어쓰지 않는다. 이는 해당 공급자의 코드 목록을 기록한 것이며 다른 행정 자료와의 정합성은 별도 확인 대상이다.

## 화면·서버 반영

`/store-api`에서 지역과 업종을 **명칭 (코드)**로 선택한다. 기본은 대전 전체다. 지역 구분에 따라 시도 → 시군구 → 행정동을 선택하고, 업종은 대분류 → 중분류 → 소분류로 범위를 좁힌다. 하위 업종을 먼저 선택해도 공식 부모 분류를 함께 채운다.

서버도 같은 스냅숏에서 코드 존재 여부와 업종 부모 관계를 확인한다. 형식만 맞는 임의 코드, 존재하지 않는 코드, 서로 다른 부모의 업종 조합은 외부 호출 전에 400으로 반환한다.
