# KAN-24 행동 이력 기반 개인화 시그널 기획 명세

> KAN-24의 `personalFit.behavior.v1`이 시민의 실제 사용 이력을 바탕으로 후보 가게에 어떤 점수를 부여해야 하는지 정의하는 기획 명세다. 제품 목적·입출력·업무 규칙·예외·수용 기준을 현재 구현 범위에 맞춰 설명한다. 점수 계산과 조회는 구현됐으며 실제 발급 서비스 활성화와 추천 품질 평가는 후속 범위다.

- 상위 — [KAN-22 문서 안내](README.md).
- 서비스 기획의 전체 범위 — S6는 데이터 확보·임베딩 모델·화면 설명·실증까지 포함한다. 이 명세는 그중 KAN-24의 점수 준비·조회 동작을 다루며, 구현 계약과 범위 결정은 [KAN-23 설계](design.md)에서 확인한다.
- 기술 설명 — [로직과 노드 흐름](personal-fit-flow.md)에서 준비·조회 다이어그램, 계산식, 수치 예제와 노드별 검사를 확인한다.
- 명세 지위 — 이번 구현 버전의 제품 동작을 정리한 스냅숏이다. 서비스 전체의 출시 승인이나 실증 완료를 의미하지 않는다.
- 확인 시점 — 2026-09-13, 코드 기준 `4bacea8`. 볼트 명세 작성 시점 이후 변경은 문서에 한정되며 앱·패키지 코드는 동일하다.

## 1. 목적과 점수의 의미

- 목적 — 시민에게 관심 업종을 직접 입력받지 않고, 실제로 이용한 가게의 특징과 비슷한 쿠폰 사용처를 평가한다.
- 해결할 문제 — 모든 시민에게 같은 가게 순위를 적용하면 서로 다른 이용 성향을 반영할 수 없다.
- 대상 — 실제 사용자 ID가 확인된 시민 한 명과 이미 구성된 후보 가게 집합이다.
- 평가 단위 — 시민과 후보 가게의 조합이다. 같은 가게라도 시민의 이력이 다르면 점수가 달라질 수 있다.
- 점수 의미 — 관측된 이용 가게 특징과 후보 가게 특징의 방향 유사성이다.
- 점수 해석 — 같은 준비 요청에서 높은 점수는 더 유사한 후보임을 뜻한다. `0.8`을 80% 사용 확률이나 만족도 80점으로 해석하지 않는다.
- 기대 편익 — 선호 입력과 사용처 탐색 부담을 줄이는 것이다. 실제 사용률·생활비 절감 개선은 아직 검증되지 않았다.
- 비목표 — 수혜 시민 선정, 발급 자격, 금액, 기한, 예산, 거리, 가격, 영업 여부를 이 신호가 결정하지 않는다.
- 추정 제외 — 가게 사용 이력만으로 실제 구매 메뉴나 시민의 소득·건강·복지 자격을 추정하지 않는다.

| 계산 버전 | `personalFit.behavior.v1` |
| 점수 준비 | 구현 완료 |
| 시민별 동기 조회 | 구현 완료 |
| 거래·사용자 정정 반영 | 제공된 입력의 정제 규칙으로 구현 |
| 가게 벡터 생성·모델 실행 | 범위 밖 |
| 실제 거래 수집·DB 어댑터 | 범위 밖 |
| 발급 서비스 등록·결합 가중치 | 범위 밖 |
| 추천 이유 문장·화면 | 범위 밖 |
| 실사용 개인화 효과 평가 | 미실시 |

- AI와 계산의 경계 — 가게의 의미 벡터 생성이 상위 기획의 AI 역할이다. 이번 신호는 주어진 수치 벡터를 이용해 규칙에 따라 계산한다.
- 모델 독립성 — 특정 모델이나 384차원을 코드에 고정하지 않는다. 한 준비 요청에서 사용하는 벡터의 명세와 차원이 같아야 한다.
- 서비스 연결 상태 — 실제 쿠폰 발급 서비스에는 `random`만 등록되어 있다. 이 명세의 개인화 점수가 현재 발급 결과에 반영된다고 설명하지 않는다.
- SSOT — 이번 버전의 제품 동작은 이 명세를 기준으로 읽고, 산식·검사 순서는 [로직과 노드 흐름](personal-fit-flow.md)을 기준으로 읽는다.

## 3. 입력과 출력 계약

### 입력

- 시민 — 비어 있지 않은 `citizenId` 하나를 제공한다.
- 후보 — 비어 있지 않은 가게 목록을 제공한다. 각 항목은 가게 ID와 내용 버전을 가지며 가게 ID는 중복될 수 없다.
- 기준 시각 — `asOf`로 관측 구간과 알 수 있었던 정보의 경계를 고정한다. 함수가 실행 시점의 현재 시각을 임의로 읽지 않는다.
- 사용 사건 — 거래 ID·정정 차수·실제 사용자·가게·사용 시각·기록 시각·상태·순사용액·당시 내용 버전을 제공한다.
- 가게 벡터 — 가게 ID·내용 버전·벡터 명세·알려진 시각·검증 시각·수치 성분을 제공한다.
- 파라미터 — 생략하면 기본값을 적용한다. 명시적으로 잘못된 값을 주면 호출 오류로 거부한다.
- 수집 전제 — 최신 정정에서 사용자가 바뀐 사실을 잃지 않도록 필요한 거래의 정정 이력을 제공해야 한다. 신호가 누락된 원천 정정을 외부에서 찾아오지는 않는다.
- 상태 경계 — 사용 사건의 입력 상태는 `confirmed` 또는 `cancelled`다. 원천의 미확정 상태를 이 계약에 연결하는 일은 수집 계층의 후속 책임이다.

### 출력

- 준비 결과 — 시민 ID, 기준 시각, 신호 버전, 준비한 후보 ID·내용 버전 목록, 활성 여부, 비활성 이유, 가게별 점수를 반환한다.
- 활성 결과 — `enabled=true`, `reason=null`이며 모든 준비 후보의 점수가 존재한다.
- 비활성 결과 — `enabled=false`이며 이유 하나와 모든 준비 후보의 정확한 0점을 반환한다.
- 점수 조회 — 후보의 시민 ID와 가게 ID로 이미 준비된 숫자 하나를 반환한다.
- 결과 보호 — 결과와 후보 목록·점수 객체는 복사·동결한다. 입력 원본이 나중에 바뀌어도 이전 결과는 유지된다.
- 출력 제외 — 내부 시민 프로필 벡터, 후보별 추천 이유 문장, 사용 확률, 선택된 최종 가게, 결합 가중치는 반환하지 않는다.
- 상위 기획과 차이 — `reasonByMerchantId`, `snapshot_id`, `profile_version`은 이번 준비 결과의 필드가 아니다. 이번 버전은 시민 단위 `reason`과 `signalVersion`을 사용한다.

## 4. 사용 이력과 채점 정책

### 이력 정책

1. 기준 시각까지 알려진 거래 정정에서 가장 큰 revision을 고른다.
2. 최신 정정의 실제 사용자가 대상 시민이며 확정 상태이고 순사용액이 양수인 사건만 남긴다.
3. 기본 90일 관측 구간에 들어온 사용 사건만 남긴다.
4. 같은 가게·같은 한국 날짜에서는 가장 최근 사건 하나만 반영한다.
5. 사건 당시 내용 버전과 후보의 지정 내용 버전에 맞는 벡터를 검증한다.
6. 최근성 및 가게별 상한을 반영한 시민 프로필과 후보 벡터의 유사도를 계산한다.

- PF-01 실제 사용자 — 쿠폰 최초 소유자가 아닌 실제 사용자의 이력에 반영한다. 실제 사용자가 불명확하면 긍정 이력에서 제외한다.
- PF-02 정정 우선 — 최신 정정이 취소·타인 사용·0원으로 바뀌었다고 이전 유효 기록을 되살리지 않는다.
- PF-03 중복 제한 — 같은 거래·revision의 동일 데이터는 중복을 접는다. 내용이 충돌하면 시민 전체 계산을 비활성화한다.
- PF-04 관측 경계 — 사용 시각은 `[asOf-90일, asOf)`다. 시작 시각은 포함하고 기준 시각 정각의 사용은 제외한다.
- PF-05 날짜 구분 — 하루 묶음은 `Asia/Seoul` 기준이다. 같은 사용 시각의 사건은 거래 ID 문자열 오름차순으로 하나를 고른다.
- PF-06 금액 독립 — 순사용액의 양수 여부만 본다. 큰 결제 금액이 더 강한 취향을 뜻하지 않는다.
- PF-07 시간 일치 — 과거 이력의 벡터는 사용 당시까지 알려지고 검증된 버전이어야 한다. 후보 벡터는 준비 시각까지 알려지고 검증된 지정 버전이어야 한다.
- PF-08 누락 처리 — 필요한 과거 내용 버전을 현재 버전으로 대체하거나 일부 누락 가게만 후보에서 제거하지 않는다.

### 점수 정책

| 설정 | 기본값 | 제품 의미 |
| --- | --- | --- |
| 관측 기간 | 90일 | 최근 이용 성향의 범위 |
| 최근성 반감기 | 30일 | 30일 더 오래된 이력의 가중치가 절반 |
| 가게별 가중치 상한 | 2 | 반복 이용 가게의 기여 제한 |
| 날짜 기준 | `Asia/Seoul` | 같은 날 중복 이용의 경계 |
| 최소 유효 노름 | `1e-12` | 방향을 정의하기 어려운 벡터·프로필 제외 |

- PF-09 반복 상한 — 같은 가게의 내용 버전이 달라도 가게 전체 가중치에 상한 하나를 적용한다.
- PF-10 점수 범위 — 시민 프로필과 후보 벡터의 코사인 유사도를 `[0,1]`로 제한한다. 음수 유사도는 활성 0점이다.
- PF-11 후보 유지 — 이미 이용한 가게도 후보로 채점할 수 있다. 신규 가게도 필요한 벡터가 준비되면 채점할 수 있다.
- PF-12 최소 이력 — 유효 사건 한 건으로도 프로필을 만들 수 있다. 별도의 최소 거래 수 기준이나 확신도 기준은 두지 않는다.
- PF-13 결정성 — 같은 입력이면 점수와 비활성 이유가 같아야 한다. 조회는 난수를 소비하거나 재계산하지 않는다.
- 수치 예제와 정확한 산식 — [로직과 노드 흐름](personal-fit-flow.md)을 참조한다.

## 5. 예외와 대체 처리

- 데이터 부족·무효로 인한 비활성은 정상적인 준비 결과다. 호출 계약 위반은 예외다.
- 비활성 단위는 시민 한 명의 준비 후보 전체다. 여러 시민의 결과를 담은 context에서 다른 시민까지 비활성화하지 않는다.
- 준비 비활성 이유 — `INVALID_HISTORY`, `NO_HISTORY`, `MISSING_VECTOR`, `INVALID_VECTOR`, `INVALID_PROFILE`이다.
- 이력 없음은 벡터 검사보다 먼저 판정한다. 이력과 벡터가 모두 없으면 `NO_HISTORY`다.
- 필요한 벡터 하나라도 없거나 무효이면 해당 시민의 모든 후보를 0점으로 반환한다.
- 프로필 방향을 만들 수 없거나 내적이 비유한이면 `INVALID_PROFILE`이다.
- 시민의 준비 결과가 Map에 없으면 조회는 0을 반환한다. 비활성 결과도 조회는 0을 반환한다.
- 다른 시민의 결과가 잘못 연결되면 비활성이어도 `CITIZEN_MISMATCH` 오류다.
- 활성 결과에서 후보 소유 키가 없으면 `CANDIDATE_NOT_PREPARED`, 점수가 유효한 `[0,1]` 숫자가 아니면 `INVALID_SCORE` 오류다.
- 대체 책임 — 이 신호는 다른 신호를 실행하거나 결합 가중치를 바꾸지 않는다. 비활성 시 다른 신호 또는 random을 사용할지는 후속 서비스 연결에서 결정한다.
- 기획 구분 — 상위 기획의 random 자동 전환·유효 가중치 재설정은 이번 코드의 완료 기능이 아니다.

## 6. 재준비와 호출자 책임

- 준비 단위 — 시민 한 명·후보 집합·기준 시각을 고정해 계산하고 반복 조회에 재사용한다.
- 재준비 조건 — 후보 추가·삭제, 후보 내용 버전 변경, 새 사용, 취소, 사용자 정정, 벡터 명세 변경, 파라미터 변경을 반영하려면 새 입력으로 준비한다.
- 시간 갱신 — 시간이 흘러 최근성이나 관측 구간이 바뀐 결과를 사용하려면 기준 시각도 갱신해 재준비한다.
- 교체 범위 — 호출자가 해당 시민의 context 항목을 교체한다. 다른 시민의 결과나 이전 준비 결과는 유지한다.
- 자동화 경계 — 신호 자체에 캐시 만료, 변경 감지, DB 저장, 갱신 스케줄러는 없다.
- 버전 책임 — 점수 조회는 가게 ID만으로 찾는다. 같은 ID의 내용 버전 변경을 자동 감지하지 않는다.
- 사용자 설명 — 추천 이유와 데이터 부족 안내 화면은 별도 구현이 필요하다. 이번 출력만으로 구체적인 구매 메뉴나 확률을 표시하지 않는다.

## 7. 수용 기준과 검증 상태

- AC-01 시민 분리 — 같은 가게라도 U1과 U2의 준비 점수가 다르면 각 시민의 값을 반복해서 정확히 조회한다. 대응 규칙은 PF-01·PF-13이다.
- AC-02 정정 반영 — 취소·사용자 변경의 최신 revision을 반영하고 이전 정상 사건을 되살리지 않는다. 대응 규칙은 PF-02·PF-03이다.
- AC-03 시간 경계 — 90일 시작 포함·끝 제외, KST 자정, 기록·벡터 시점의 경계를 지킨다. 대응 규칙은 PF-04·PF-05·PF-07이다.
- AC-04 금액과 반복 — 양수 결제 금액 크기에 따라 가중하지 않으며 같은 날 중복·가게별 기여를 제한한다. 대응 규칙은 PF-05·PF-06·PF-09다.
- AC-05 산술 — 고정 가상 벡터의 손계산 점수·순위와 일치하고 결과가 `[0,1]`의 유한한 숫자다. 대응 규칙은 PF-10·PF-13이다.
- AC-06 비활성 — 필요한 벡터 하나의 누락과 프로필 실패가 이유 및 전 후보 0점으로 드러난다. 대응 규칙은 PF-08이다.
- AC-07 조회 오류 — 시민 불일치, 활성 상태의 미준비 후보, 잘못된 활성 점수를 조용한 0점으로 숨기지 않는다.
- AC-08 재준비 격리 — U1의 후보·내용 버전을 갱신해도 U2와 이전 준비 결과는 보존된다.
- 확인된 범위 — 2026-09-13 관련 테스트 3파일 104개 통과 기록이 있다. 이번 기획 명세 작성에서는 테스트를 새로 실행하지 않았다.
- 검증 상세 — [최종 검증 기록](personal-fit-validation.md) 및 [로직과 노드 흐름](personal-fit-flow.md)을 참조한다.
- 품질 미검증 — 테스트 통과는 벡터 계산과 계약 검증이다. 실제 취향 적합성·이용률 향상·추천 공정성을 입증하지 않는다.
- 출시 전 남은 판단 — 원천 사용 이력 연결, 과거 가게 정보, 모델·전처리 버전, 서비스 결합, 이유 표시, 갱신·삭제 정책, 평가 기준은 상위 기획의 후속 범위다.
