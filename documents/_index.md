- 2026-09-15 — 공모전 붙임4 「제안 요약서」의 본문 초안을 [제안요약서 초안](제안요약서-초안.md) 으로 작성하고 두 차례 다듬었다. 항목 1)~5)를 서식 순서대로 채웠고, 제출 본문과 작성 노트를 구분해 서식에 옮길 문장만 본문으로 남겼다. 근거 수치는 출처·기준연도와 함께 저장소 안에 직접 옮겨 적었다(카드포인트 연 소멸액 937억 원·미사용 총액 2조 9,000억 원, 대구로페이 2026년 발행 3,000억 원·전년 대비 -24.4%, 대구 순창업 -2,287개·5년 생존율 47.0%). **1-3 주요 기능 표는 코드에서 확인된 네 가지만 올렸다** — `salesRecovery` 는 산식만 있고 구현이 없으며 `personalFit` 은 점수 준비·조회까지만 서 있고 발급 서비스에 연결되지 않아 둘 다 뺐다. 5-2 검증 수치는 현재 브랜치에서 재실행한 값(단위·통합 357건 = API 197 / 화면 147 / 파일 DB 13, 브라우저 e2e 6건, `typecheck` 7/7, 빌드 성공)으로 채웠다. 제출 본문은 A4 환산 약 5.9장이라 5장 기준을 넘으며, 줄이는 순서를 초안의 미결에 적어 두었다. 2-1 제출용 구조도, 5-1 화면 캡처 4장, 5-2 가중치 대비 도표, 4-1 지표 산출은 아직 없다.

- 2026-09-14 — 시연용 가게 벡터 데이터를 `data/seed/` 에 커밋했다. `merchant-vectors.json` 13건과 `merchant-contents.json` 13건이며 가맹점은 12곳으로 늘렸다. **임베딩 생성 코드는 저장소에 두지 않는다** — 생성은 저장소 밖 일회성 배치이고 로직·조건은 [가게 벡터 모델](가게-벡터-모델.md) 이 기록한다. 전 레코드가 384차원·노름 1(오차 `1e-6` 이내)이며 코사인 실측값은 0.87~0.97 구간에 몰린다. `data/seed/` 파일은 `bootstrapFromSeed` 가 그대로 복사하므로 `pnpm db:seed` 만으로 컬렉션이 되고 코드 변경이 없다. 루트 `test` 197건과 `typecheck` 7/7이 통과했다. e2e 3건 실패는 이 변경 이전부터 `main` 에 있던 것으로 확인했다.
- 2026-09-14 — 가게 벡터 생성(KAN-25)의 모델과 구성 요소를 확정해 [가게 벡터 모델](가게-벡터-모델.md) 을 만들었다. 임베딩 모델은 `intfloat/multilingual-e5-small`(MIT, 384차원)이고 ONNX 미러 revision과 dtype `fp32` 를 고정했다. 벡터 구성 요소는 업종 라벨과 대표메뉴 최대 5개 둘로 좁혔다. 같은 날 공모전 제공 CSV 242,573행을 프로파일링해 **가맹점 식별자·가맹점명·대표메뉴가 없고 업종명 11종만 있다**는 사실을 확인했다. 따라서 현재 데이터로 만들 수 있는 것은 가게별 벡터가 아니라 업종별 벡터 11개이며, 대표메뉴 확보는 공공데이터포털 인증키 발급이 선행이다. 모델 실행은 미실시다.

## 이 파일을 갱신하는 규칙

- 문서를 만들거나 지웠으면 "문서 목록"을 같은 커밋에서 갱신한다. 목록에 없는 문서는 없는 문서다.
- 결정은 각 주제 문서에 `- YYYY-MM-DD — <결정 한 줄>` 로 쌓는다. 뒤집힌 결정도 지우지 않고 뒤집은 사실을 새 날짜로 적는다.
- 날짜는 절대 날짜로 적는다. "어제", "지난주"는 쓰지 않는다.
- 맨 위 "갱신" 날짜를 함께 고친다.
- 근거는 다른 곳에 미루지 않고 여기에 직접 옮겨 적는다 (`documents-first` §6).
