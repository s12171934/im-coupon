## 아직 기록되지 않은 것

결정은 내려져 있으나 이 폴더에 아직 문서로 남지 않은 주제들이다. 해당 주제의 작업을 시작할 때 문서로 만들면서 함께 정리한다.

- [ ] **문제정의 근거 수치** — 제안 서류에 쓸 대구 상권·소비 실증 수치. 구현에 걸리지 않으므로 후순위다
- [ ] **어뷰징 방지 룰의 판별식** — 방지 대상과 방향은 [쿠폰 도메인 규칙](쿠폰-도메인-규칙.md) 에 있으나, 탐지 조건의 수치가 정해지지 않았다

## 진행경과

- 2026-09-05 — 모노레포 골격을 세웠다. `apps/web`·`apps/api`·`packages/contracts`·`packages/db`·`e2e` 다섯 워크스페이스가 서고, 화면에서 API 를 거쳐 JSON 파일 DB 까지 닿는 경로 하나(저장소 상태 표시)가 관통한다. 단위 테스트 9+2+2건과 e2e 1건이 통과하며, `pnpm dev` 한 명령으로 전체가 뜬다. 쿠폰 도메인 로직은 아직 없다.
- 2026-09-05 — 기획 원본을 저장소로 수거했다. [쿠폰 도메인 규칙](쿠폰-도메인-규칙.md) 과 [프로토타입 범위](프로토타입-범위.md) 를 만들어, 발급·소비 규칙과 목 데이터·파라미터 방침이 저장소 안에서 선다. [지라 티켓 연결](지라-티켓-연결.md) 로 티켓 대응 관계도 함께 들여왔다. 구현은 아직 시작하지 않았다.
- 2026-09-05 — 개발 서버가 자기 워크트리 삭제 후에도 살아남아 포트를 붙드는 문제를 막았다. API 는 자기 소스 디렉터리가 사라지면 스스로 종료하고, 포트 선점 실패는 점유자를 찾는 안내로 바뀌었으며, e2e 는 남이 띄운 서버를 재사용하지 않는다. `.gitignore` 도 산출물·테스트 결과·환경 변수·편집기·운영체제 파일을 모두 덮도록 정리했다.
- 2026-09-05 — 문서에 다이어그램을 넣었다. 쿠폰 라이프사이클 상태기계, 발급 대상 결정 파이프라인, 혜택 이분화 경로, 워크스페이스 의존 방향, 개발 서버 기동·수명, 만드는 순서의 선행 관계, 목 데이터 교체 지점, 티켓 계층 여덟 장이다. 형식은 Mermaid 인라인으로 고정했고, 규칙은 [저장소 구조와 기술 스택](저장소-구조와-기술-스택.md) 의 "문서의 다이어그램" 절에 있다.
- 2026-09-05 — 여덟 장의 다이어그램 형식을 바꿨다. Mermaid 인라인을 걷어내고 `documents/diagrams/` 아래 JSON 사양 + 탐색 가능한 HTML + 인라인용 PNG 세 벌로 다시 그렸다. 문서 본문에는 PNG 가 보이고 그 아래 HTML 링크가 붙는다. 그림이 지고 있던 주장은 그대로이고, 미결이던 것은 그림 안에서도 미결로 남아 있다. 새 규칙은 [저장소 구조와 기술 스택](저장소-구조와-기술-스택.md) 의 "문서의 다이어그램" 절에 있다.

- 2026-09-06 — 에픽 KAN-13(프로토타입 쿠폰 발급)의 설계문서를 [KAN-13/design.md](KAN-13/design.md) 로 작성했다. 발급 신호는 랜덤 하나만 구현하되 가중치 결합 구조는 유지하고, 트리거는 시연 버튼, 후보 데이터는 정적 시드로 축소한 범위다. 구현 브랜치 일곱 개의 스택·API 계약·RED 테스트가 정의되어 있고, 구현은 아직 시작하지 않았다.

## 미결

구현에 직접 걸리는 것만 둔다.

- [ ] **기획 노선 확정 대기.** 공용 풀·점유(찜하기)·블록체인 축 세 가지를 함께 정해야 하고, 이것이 나머지 미결 전체의 선행이다. 선택지와 찬반 근거는 [쿠폰 도메인 규칙](쿠폰-도메인-규칙.md) 미결에 있다. 이 결정이 `packages/db` 의 동시 쓰기 보호 필요 여부까지 가른다
- [ ] 소유자 보상의 비환금화 방식을 택일한다 — 발급 우선권 / 기여도 점수 / 봉사·기부 마일리지. 상세는 [쿠폰 도메인 규칙](쿠폰-도메인-규칙.md)
- [ ] 타겟팅 판별식을 수치화한다. 발급 알고리즘의 입력이 여기서 정해진다
- [ ] 프로토타입 제출 형태(구현 코드 / 시연 영상)와 그에 따른 실행·배포 절차를 정한다. 상세는 [프로토타입 범위](프로토타입-범위.md)

## 이 파일을 갱신하는 규칙

- 문서를 만들거나 지웠으면 "문서 목록"을 같은 커밋에서 갱신한다. 목록에 없는 문서는 없는 문서다.
- 결정은 각 주제 문서에 `- YYYY-MM-DD — <결정 한 줄>` 로 쌓는다. 뒤집힌 결정도 지우지 않고 뒤집은 사실을 새 날짜로 적는다.
- 날짜는 절대 날짜로 적는다. "어제", "지난주"는 쓰지 않는다.
- 맨 위 "갱신" 날짜를 함께 고친다.
- 근거는 다른 곳에 미루지 않고 여기에 직접 옮겨 적는다 (`documents-first` §6).
