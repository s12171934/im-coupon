# 상권회복 시연 후보

## 결정

- 2026-09-16 — D1 공공 업종 기반 mock으로 상권회복 비교 시연 후보를 확정한다. D0의 11개 업종 대응 여부를 후보 자격으로 사용하지 않는다.
- 발급 후보는 기존 공공 가게 12곳이다. 가상 가게 48곳은 구별 비교 통계에만 포함한다. 발급용 `merchants` 컬렉션에 가상 가게를 추가하지 않는다.
- 동일한 12개 소분류를 대전 5개 구에 배치한 비교 모집단 60곳과 202604·202605·202606 소비 이력을 seed 및 현재 runtime에 함께 반영한다.

## 데이터 구조와 현재 결과

| 컬렉션 | 건수 | 역할 |
| --- | ---: | --- |
| merchants | 12 | 기존 발급 후보, 유지 |
| comparison-merchants | 60 | 공공 가게 12곳과 가상 가게 48곳의 비교 모집단 |

| city-consumption-monthly | 36 | 대전 전체 12개 업종 × 3개월 소비액·건수 |

| sales-recovery-dataset | 1 | 생성기 판본·기준월·평가 시각·출처·품질 결과 |

모든 신규 JSON 컬렉션은 레코드 배열이다. 현재 runtime도 신규 7개 컬렉션을 함께 갱신했다. DB 초기화는 기존 컬렉션이 하나라도 있으면 새 seed를 자동 복사하지 않으므로, 생성기가 직접 신규 컬렉션을 적용한다. 기존 쿠폰·포인트·가게·개인화 이력을 덮어쓰지 않는다.

소비 이력은 `id`, `actualUserId`, `merchantId`, KST ISO 시각 `consumedAt`, 원 단위 `amount`, `currency`, `sourceKind`로 구성한다. 공공 업종·지역 코드는 `merchantId`로 비교 가게에 연결한다. 가상 가게에는 존재하지 않는 공공 상가 ID나 벡터를 만들지 않는다.

`comparison-consumption-events`는 **상권 집계를 위한 합성 거래**다. 현재 개인화가 읽는 `personal-fit-events`와 목적이 다르며, 새 비교 이력을 개인화에 중복 합산하지 않는다. 기준 시점보다 나중에 확보한 가게 벡터를 4~6월 거래에 소급 연결하지도 않는다.

## 후보 판정

후보를 평가하는 시각과 소비 통계의 기준월은 별개다. 개인화용 내용·벡터는 생성 실행 시각(또는 명시한 ISO 시각)을 기준으로 확인하며 통계는 202606을 기준으로 확인한다.

1. 후보는 `merchants`에 있는 기존 가게로 제한한다. D1 소분류 및 대전 지역 연결이 없는 입력은 데이터 생성 단계에서 실패시킨다.
2. 해당 구·업종의 4~6월 관측과 대전 전체 같은 업종의 관측이 모두 있어야 한다.
3. 직전 두 달 일평균이 0이면 해당 비교는 불가다. 없는 관측을 0으로 채우지 않는다.
4. 평가 시점까지 알려지고 확인된 최신 가게 내용과 그 버전의 벡터가 필요하다. 최신 내용에 벡터가 없다고 이전 내용의 벡터로 대체하지 않는다.
5. 벡터 값이 유효한지, 후보들이 같은 모델 명세와 차원을 사용하는지 확인한다.

`eligible`은 **시연 후보의 데이터 준비 여부**다. 특정 시민의 개인화 점수가 계산된다는 보장은 아니다. 시민별 이력 유무·소비 당시 벡터 확인은 기존 개인화 계산에서 추가로 판정한다. 평가 이후 원천 데이터가 바뀌면 후보 목록도 다시 생성해야 한다.

제외 사유는 `MISSING_STATISTICS`, `LOCAL_MISSING_REGION_MONTH`, `CITY_MISSING_REGION_MONTH`, `LOCAL_ZERO_DENOMINATOR`, `CITY_ZERO_DENOMINATOR`, `MISSING_CONTENT`, `MISSING_VECTOR`, `AMBIGUOUS_VECTOR`, `INVALID_VECTOR`, `INCOMPATIBLE_VECTOR_SPACE` 등으로 기록한다. 부적격 후보를 별도 목록에서 숨기지 않고 `eligible: false`와 사유를 남긴다.

## 집계와 감소율

```text
이전 일평균 = (4월 금액 + 5월 금액) / 61
현재 일평균 = 6월 금액 / 30
감소율 = 1 - 현재 일평균 / 이전 일평균
상대 감소율 = 해당 구 감소율 - 대전 전체 감소율
```

대전 전체는 각 월의 5개 구 소비액을 먼저 합산한 후 감소율을 계산한다. 구별 감소율을 단순 평균하지 않는다. 증가하면 감소율이 음수이고, 이전 금액이 양수인 상태에서 현재 관측이 0이면 감소율은 1이다. 지역·월 누락, 비정상 금액, 0분모는 사유와 `null`을 반환한다. 이 차이는 아직 최종 회복 점수로 정규화된 값이 아니다.

이번 생성 결과에서 기대 월별 180개 키 누락과 거래 ID 중복은 0건이다. 거래→구별→대전 전체 총금액은 모두 309,890,000원이다. 이는 실제 대전 소비액이 아닌 합성 자료의 합계다.

## mock 가정

- 하루 거래 수는 4월 4건·5월 5건, 6월은 구·업종 순서에 따라 2·3·5·6·7건으로 생성한다. 거래 금액은 5,000~20,000원의 결정적 패턴이다. 계절성·인구 구성·실제 상권 규모를 반영한 추정이 아니다.
- 기존 가게의 과거 영업 여부, 당시 업종·행정구역 경계는 검증하지 않았다. 공공 코드와 실제 가게 이름이 있다는 사실만으로 이 거래를 실측 자료로 해석하면 안 된다.
- 선택한 12개 업종만 대상으로 하며 D1의 전체 1,255개 업종을 소비 데이터로 생성한 것은 아니다.

## 생성과 검증 범위

`node scripts/generate-d1-consumption.mjs [평가시각 ISO]`

외부 네트워크 없이 현재 seed·공공 코드·내용·벡터에서 생성한다. `IM_COUPON_DATA_DIR`로 runtime 경로를 지정할 수 있다. seed와 runtime 가게·시민 연결이 다르거나, 동일한 신규 컬렉션 이름을 다른 데이터가 이미 사용하면 덮어쓰지 않고 중단한다. 이 생성기가 관리하는 7개 컬렉션만 재생성한다. 각 파일은 임시 파일에서 교체하지만 다중 파일 트랜잭션은 아니다.

생성 과정에서 거래 참조·금액·중복 ID·기대 집계 개수·총액 일치를 확인했다. 결측·0분모·최신 내용 버전의 벡터 누락 사례에 대한 자동 테스트를 작성했으며 사용자 지침에 따라 실행하지 않았다. 빌드·타입 검사도 실행하지 않았다.
