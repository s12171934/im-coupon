# 유저별 소비 이력과 공공 코드

## 결정

- 2026-09-16 — 기존 `personal-fit-events` 컬렉션에 공공 상가·업종·지역 분류를 추가했다. 소비 이력을 별도 mock 폴더에 복제하지 않고 seed와 현재 runtime에 반영한다.
- D1은 상가정보이므로 공식 개인 소비 타입이 없다. 프로젝트의 `UserConsumptionEvent`를 정의하고 개인화 입력이 이를 상속한다. 새 mock은 `D1MockConsumptionEvent`의 필수 분류 필드를 채운다.

## 데이터 계약

| 필드 | 의미 |
| --- | --- |
| actualUserId | 실제 사용 역할의 가상 시민 ID; 쿠폰 소유자와 혼동하지 않음 |
| merchantId | 프로젝트 가게 ID |
| usedAt / recordedAt | 소비·기록 시각, UTC epoch 밀리초 |
| netAmount / currency | 취소분 제외 금액 / KRW |
| transactionId / revision / status | 거래 식별·정정 차수·확정 또는 취소 |
| contentVersion | 소비 사건과 연결된 기존 가게 내용·벡터 버전 |
| sourceKind | 이번 이력은 mock; 공공 실측 소비액이 아님 |
| publicStoreContext | 공공 상가 ID와 대·중·소분류, 시도·구·행정동 코드 및 각각의 명칭 |

분류에는 상가 기준월·조회 시각, 코드 목록 조회 시각·기준일도 보관한다. 이는 현재 확보한 공공 자료로 mock에 분류를 붙인 기록이다. 거래 당시 실제 업종·행정구역이 동일했다고 입증하는 과거 스냅샷이 아니다.

`publicStoreContext`의 `publicStoreId`는 내부 `merchantId`와 다르다. 지역은 고객 주소가 아닌 가게 소재지다. 시도 코드로 구 이름을 좁히고, 구 코드로 행정동 이름을 좁힌 뒤 유일한 코드를 연결한다. 코드가 없거나 중복이면 쓰기 전에 중단한다.

## 반영 범위

기존 seed와 runtime의 가상 시민 20명·소비 이력 120건씩에 분류를 추가했다. 기존 거래 ID·금액·시각·내용 버전은 유지했다. 개인화는 같은 컬렉션을 읽으며 업종 메타데이터 추가 자체가 점수 가중치나 벡터 계산을 바꾸지는 않는다.

`mock-personal-fit:` 거래만 변환한다. 그 외 기존 이력은 관측/가상 출처나 분류를 임의로 부여하지 않으며 호환용 기본 계약에서는 추가 필드를 선택값으로 둔다.

## 재생성과 기존 이력 갱신

- `node scripts/generate-personal-fit-mock.mjs` — 공공 분류를 포함한 새 mock을 seed와 runtime에 생성. 기존처럼 시각을 재산정한다.
- `node scripts/enrich-personal-fit-context.mjs` — 기존 mock의 시각·금액을 보존하고 분류만 연결. 각 저장소의 가게·시민을 기준으로 처리한다.
- `IM_COUPON_DATA_DIR`를 지정하면 해당 runtime 경로를 사용한다. 두 목적지의 참조 데이터를 모두 확인한 후 파일별 임시 파일 교체로 저장한다. 두 파일을 하나의 트랜잭션으로 저장하는 구조는 아니다.

코드 대응 함수는 `scripts/public-consumption-context.mjs`, 공유 타입은 `packages/contracts/src/user-consumption.ts`에 있다.
