# 발급 쿠폰과 소비 시연 연결

소비 화면은 `/api/coupons/issue`로 발급한다. 소비 전용 쿠폰 생성 API는 제거했다.
발급에는 main의 KAN-24 개인화 점수 계산을 연결했다. `personal-fit-events`·`merchant-contents`·`merchant-vectors`를 읽고
시민별 점수를 준비한 뒤 랜덤 0.3·개인화 0.7의 기본 가중치로 후보를 선택한다. 입력 파일·재생성 방법은
[발급 후보 목 데이터](../data/seed/README.md)에 있다. 소비 화면에도 발급 결과의 신호별 점수·합산 점수·비활성 사유를 표시한다.
`issued-coupons`의 발급 ID·시민 ID·가맹점 ID·액면·배분 비율·두 기한을 그대로 읽으며,
최소 결제액이나 별도의 고정 페이백 금액을 만들지 않는다. 결제 버튼은 실제 결제망 호출이 아닌 사용 시연이다.

## 금액과 사용자

- 본인 사용: `ownerId === consumerId`이면 `faceValue` 전액을 소비자에게 지급한다.
- 타인 사용: `faceValue × benefitSplit.consumerRatio`를 원 단위 반올림해 소비자에게 지급한다.
  나머지를 소유자 리워드로 기록해 두 금액의 합이 액면과 일치하게 한다.
- 요청은 `consumerId`, 혜택 내역은 `recipientId`로 구분한다. 이름은 표시용이다.
- 소유자와 소비자는 시민 목록에서 선택한다. 같은 이름이어도 ID가 다르면 다른 사람이다.

## 기한과 상태

발급의 `held`를 시작으로 소유자 전용 기한(`heldUntil`)에 `public`, 전체 기한(`expiresAt`)에 `expired`가 된다.
공개 쿠폰은 한 시민이 동시에 한 장만 `reserved`로 점유하며, 점유 기한은 3시간과 전체 기한 중 이른 시각이다.
점유 기한이 끝나면 다시 공개된다. 사용된 쿠폰은 `used`를 유지한다.
소유자 전용 상태에서는 소유자만, 점유 상태에서는 점유자만 사용할 수 있다.

소유자 기한 경과 시연은 `ownerReleasedAt`으로 기록한다. 발급 당시 `heldUntil`이나 `expiresAt`은 덮어쓰지 않는다.
화면은 15초마다 상태를 조회하고, 사용·점유 요청 시에는 서버가 현재 기한과 권한을 다시 판단한다.

## 저장과 이전 기록

- `issued-coupons`: 발급 당시 조건을 보존하는 원본. 소비에서 수정하지 않는다.
- `consumption-state`: 발급 ID별 점유·사용·시연 기록, 수령자별 혜택, 초기화 제외 ID를 한 레코드로 저장한다.
  사용 처리와 혜택을 같은 파일에 원자적으로 저장한다. 단일 API 프로세스 안의 소비 요청은 직렬 처리한다.
- 첫 조회 때 기존 `coupons`와 `points` 중 실제 발급 ID와 일치하는 기록만 옮긴다.
  이름으로 기록된 시민은 유일하게 일치하는 ID로 변환한다. 시민을 확정할 수 없는 점유는 이어받지 않으며,
  이전 혜택은 `legacy:` 수령자 ID로 보존한다. 기존 파일은 삭제하지 않는다.
- 초기화는 소비 시연 내역을 비우고 현재 발급된 ID를 소비 화면에서 제외한다. 이후 발급한 쿠폰부터 다시 시연한다.
  발급 화면과 내 쿠폰 화면의 발급 원본은 그대로 보존된다.

`GET /api/coupons`의 내 쿠폰 조회는 발급 원본을 반환한다. 소비 진행 상태는 `GET /api/consumption`으로 조회한다.
다중 API 프로세스의 동시 쓰기를 위한 파일 잠금은 이번 단일 프로세스 시연 범위에 포함하지 않는다.
