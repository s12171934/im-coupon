# 소비 시연 500 오류 조사 — 2026-09-14

## 원인과 복구

`couponBenefits`는 계약 소스에 추가됐지만 기존 API는 해당 함수가 없는 `contracts/dist`를 읽고 있었다.
조사 시작 당시 API PID 10163과 감시 부모 PID 90834의 명령에 새 `--conditions=im-coupon-source`가 없었다.
패키지 설정을 바꿔도 이미 실행 중인 감시 부모의 실행 옵션은 갱신되지 않은 상태였다.

공유 패키지를 재빌드하고 API 소스 변경에 따른 감시 재기동이 반영됐다. 조사 완료 시 API PID는 11747이며,
3000번 서버의 상태·시민·소유자 쿠폰·소비 조회는 모두 HTTP 200이었다.

개발 명령의 소스 진입점 설정은 유지한다. 새로 시작하는 개발 실행이 소스를 읽고 실제 함수를 가져오는 것을
별도 프로세스 테스트로 확인했다. 오래된 계약을 다시 읽는 경우에는 API 시작 단계에서 함수 존재를 검사해,
결제 버튼을 누를 때까지 오류가 숨어 있지 않게 했다.

## 추가 수정

- 발급 본문이 JSON 객체인지 확인한다. 배열 등 잘못된 요청으로 쿠폰이 발급되지 않는다.
- 소비자 ID 누락·잘못된 타입은 HTTP 400과 `소비자 ID가 필요합니다.`로 안내한다.
  기존의 공통 필터는 이 오류까지 JSON 파싱 실패로 바꾸고 있었다.
- 시민 목 데이터가 20명으로 늘어난 데 맞춰 오래된 5명 단언을 수정했다.
- 소비 HTTP 통합 테스트와 브라우저 결제 시연 테스트를 추가했다.
- E2E API·웹 포트를 환경변수로 지정할 수 있게 해 실행 중인 개발 서버와 분리했다.

결제·초기화의 쓰기 검증은 임시 데이터의 API 및 브라우저에서 수행했다.
