# 발급 후보 목 데이터

시연용 가상 시민 20명과 가상 가맹점 15곳이다. 이름·상호는 가상의 예시이며 실제 인구나 업종 분포를 대표하지 않는다.

- `citizens.json`: `cit-001`부터 `cit-020`까지 시민 ID와 표시 이름.
- `merchants.json`: `mer-001`부터 `mer-015`까지 가맹점 ID·표시 이름·업종.
- 기존 시민·가맹점 각 5건의 ID와 이름은 유지한다.
- 발급 후보는 가맹점 × 시민 전체 조합인 300건이며, 기존 발급 알고리즘이 한 조합을 선택한다.
- 소비 화면의 소유자·소비자 선택에도 같은 시민 목록을 사용한다.
- `personal-fit-events.json`: 시민당 6건, 총 120건의 가상 행동 이력. 실제 사용자 ID·거래 ID·시각·내용 버전을 포함한다.
- `personal-fit-vectors.json`: 가맹점별 5차원 시연 벡터 15건. 식사·음료·문화·생활취향·생활서비스 특징이며 학습 모델의 임베딩은 아니다.

발급은 `main`의 `preparePersonalFit`으로 시민별 점수를 준비한 뒤 `personalFitSignal`로 조회한다.
기본 합산은 `랜덤 점수 × 0.3 + 개인화 점수 × 0.7`이고 발급 화면에서 두 가중치를 조절할 수 있다.
행동 이력이 없거나 벡터가 부적합하면 개인화는 0점이며, 발급 결과에 비활성 사유를 표시한다.

행동 이력은 생성 시점 기준 최근 1·4·10·18·35·60일의 고정 데이터다. 시간이 지나 90일 관측 구간에서 벗어나면 재생성한다.

```sh
node scripts/generate-personal-fit-mock.mjs
# 동일한 기준 시각으로 재현할 때
node scripts/generate-personal-fit-mock.mjs 2026-09-14T00:00:00Z
```

생성기는 시드와 기본 런타임의 목 이력·벡터를 함께 갱신한다. 이 생성기의 거래 ID 접두와 내용 버전에 해당하는 데이터만 교체하고 다른 데이터는 보존한다.
소비 시연의 페이백 액면을 실제 결제액으로 간주하지 않는다. 현재 개인화 입력은 이 별도 목 이력이며, 소비 버튼을 누른 결과를 행동 이력으로 자동 추가하지 않는다.

새 환경에서는 API 초기화가 이 시드를 `data/runtime`으로 복사한다. 이미 존재하는 런타임 컬렉션은 자동으로 덮어쓰지 않는다.
이번 후보 확장은 기본 `data/runtime`의 시민·가맹점 목록에도 반영했다. 기존 쿠폰·소비·혜택 기록은 유지한다.
`IM_COUPON_DATA_DIR`을 따로 지정했다면 그 경로의 후보 목록에도 별도 반영해야 한다.
